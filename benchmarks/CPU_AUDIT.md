# DSP / UI CPU 审计

## 2026-10-05：按需准备插槽与完整 HQ 延迟对齐

空插槽不再预备 History、Reverb、Clouds、Chord Resonator 和 Core 的全部引擎。首次需要某个效果族时，在状态/UI 写入线程或每实例一个的后台准备线程中完成分配，再发布 ready 标记；音频只发布原子请求并保持平滑的干声过渡。已使用的效果族保留缓存，避免反复切换时释放或分配音频资源。

同机默认单频段、48 kHz / 128 samples、双声道、不开编辑器，三个实例的增量物理内存由 `136–141 MiB` 降至 `31–35 MiB`；prepare 的增量约 `9.6–9.8 MiB`，原来约 `115 MiB`。34 项相关检查通过，共 419473 条断言，包括后台类型自动化、冻结素材、共享模块和独立 Shape HQ。

加入每插槽固定延迟、Shape 模块干湿对齐和后台准备后，64 samples 的完整处理预算如下。每项三轮，取中位数；不创建编辑器，不等同于宿主 CPU 表。

| 场景 | 48 kHz | 96 kHz |
| --- | ---: | ---: |
| 默认单频段 | 7.09% | 13.85% |
| 四频段 Transformer HQ | 35.46% | 67.91% |
| 四频段 Tape HQ | 58.75% | 72.43% |

完整版本的 96 kHz Transformer HQ 比只优化磁化时的检查点多了插槽延迟对齐开销，仍低于原先 `105%` 的预算。99% 回调约为预算的 `75.71%`。原始结果见 [cpu-insert-preparation-results.json](cpu-insert-preparation-results.json)。

## 2026-10-05：Transformer 的高采样率实时余量

保持磁化方程、材料参数、绕组求解容差和采样时钟，弱耦合的磁化工作点改用 Newton 辅助校正。微小校正同步推进可逆/不可逆磁化；靠近反转或钉扎边界时保留完整第二次求值。44.1–384 kHz 多音、过载脉冲及静音尾音对照的最大输出差小于 `3.4e-10`，绕组残差仍小于 `1e-11`。

同机 M1 Pro、Release、双声道、64 samples、不开编辑器，四频段 Transformer HQ 在 96 kHz 的平均单核实时预算占用由两轮的 `105.06% / 105.09%` 降至 `57.26%`；99% 回调为预算的 `62.26%`。48 kHz 同场景为 `30.81%`。这些是连续多音的离线计算预算，不代表实际宿主的掉音次数或 CPU 表。原始测量见 [cpu-transformer-mean-field-results.json](cpu-transformer-mean-field-results.json)。

18 项磁化、电路、供电、磁带、真实多频段、HQ 辅助调制及 256 KiB 音频栈检查通过，共 660147 条断言。

## 2026-10-04：物理模型与频谱更新

这次保留磁化方程、RF 时钟和磁头滤波：缓存 Langevin 值/导数的 Hermite 系数及材料比例，复用 Transformer 已收敛的磁化状态；Tape 的不可逆磁畴仍被钉扎时省去中点求解，稳定静音后停止 RF 求解并继续推进偏磁相位。四种采样率的多音、过载脉冲及静音尾音对照中，Transformer 最大输出差小于 `8.1e-12`，Tape 小于 `2.5e-14`。独立 Tape 实时分配探针为零。

频谱按原始 FFT/像素峰值构建单调三次曲线，不提高 FFT 尺寸或改变测量读数。图层按设备缩放用软件绘制，macOS 彩色图层保留原生图像缓存，原始频谱和峰值线使用单通道遮罩。透明度变化复用图层；零透明度跳过绘制；峰值和实时曲线独立失效。

| --- | ---: | ---: |

仓库基准已加入物理 Transformer/Tape 场景，以及 `[cpu-ui]` 的新帧、缓存帧、透明帧和 1×/2× 绘制。以下为更早一轮审计，保留其当时实现及测量范围。

本轮检查了 `Source/DSP`、`PluginProcessor`、编辑器、GUI 控件、ControlPanel 和 SpectrogramPanel 的处理循环、计时器、绘制与缓存路径。目标是保留声音、逐采样调制、平滑时间常数和现有动画帧率，减少重复工作。源码审计和独立基准不能替代 DAW 内的整机 CPU 测量。

## 已实现

| 范围 | 优化 |
| --- | --- |
| 插入效果 | 缓存相同参数的非线性映射、Delay/Reverb 滤波系数、LoFi 位深量化系数；Reverb 参数变化时才更新；reset、效果切换及重新 prepare 时使缓存失效。 |
| Tape / 环形历史 | 固定滤波系数移至 prepare；普通采样不再调用 fmod；环形缓冲区使用边界判断代替整数取余。 |
| OTT DSP | 最终增益表头的 dB 换算从每采样移至块末；稳定且无调制的控制参数每块计算一次，检测器仍逐采样运行，旁路时也保留历史。 |
| Width / 模块排序 | Width 直接传入平滑后的基值，避免复制含函数对象的参数范围；排序前各读取一次插入位置，减少原子读取并保证比较器使用一致的数据。 |
| 频谱 | 缓存对数频率坐标，尺寸和 FFT 网格变化时失效；透明度动画复用几何；未显示峰值时不换算峰值 dB；峰值衰减先求最大幅值再换算 dB。 |
| FFT | 仅请求非负频率的幅值；接收帧时直接覆盖样本区域，只清零 scratch 尾部。 |
| OTT UI | 攻击/释放的指数系数每帧各算一次；先将 FFT 幅值归并到 96 列再转 dB；图形与频段控件稳定后停止请求重绘。 |
| LFO UI | 播放头与相位线仅重绘旧、新位置的窄条；修复小于 1 的物理缩放比例导致网格缓存每帧重建。 |

## 已有保护与保留行为

- 音频 scratch 预分配，异常超大宿主块使用固定容量分段；非有限输入和 denormal 保护继续保留。
- 滤波/分频已有系数缓存和平滑；LFO 波形使用查表，形状构建与逐采样处理分离。
- 主背景、控制面板、图表底图、LFO 网格和波形已有缓存；示波器、声像图、电平及多数控件动画已有可见性或状态变化判断。
- Host bypass 仍推进隐藏的湿声处理链，使恢复时的滤波器、压缩器、延时、HQ 和 LFO 状态保持连续。不能简单跳过整个 DSP。
- 关闭界面后不执行 FFT 变换，但音频线程继续维护 FFT 帧及降采样历史。暂停捕获需要单独实现可见消费者订阅和 fresh-frame epoch，避免重新打开时显示陈旧数据。

## 基准方法

原 benchmark 调用了已删除的 `processMultiBand`，部分参数还误将实际值直接传入要求 0–1 的接口。本轮移除失效场景，保留启动基准，增加 `[cpu]` 与 `[cpu-ui]`。

- 同一机器、AppleClang 17、arm64、Release `-O3 -fno-fast-math` / LTO，使用相同 JUCE 与依赖。
- DSP：48 kHz、双声道、128 / 512 samples，每次处理前恢复同一固定合成输入，预热 256 块。调制场景使用持续运行的 3 Hz 三角 LFO 调制 Delay Tone。结果包含输入复制和完整处理回调；不创建编辑器。
- UI：1000×300 的频谱、1024 bins、不显示峰值，测量几何重建。它不代表完整界面栅格化或 DAW 的 CPU 表。
- 当前工作区 `Builds` 原配置为 Debug。性能数字使用独立 Release 构建，未改动现有构建配置或安装插件。

在 Release 构建中运行：

```sh
cmake --build <release-build> --target Benchmarks
<release-build>/Benchmarks '[cpu],[cpu-ui]' --benchmark-samples 60 --benchmark-resamples 2000 --benchmark-warmup-time 300
```

## 本机 Release 测量结果

前后版本交替运行三轮，每轮 60 个计时样本、2000 次 bootstrap，表中取三轮均值的中位数。原始均值、95% 置信区间及标准差见 [cpu-audit-results.json](cpu-audit-results.json)。单位为微秒，正百分比表示观测到的耗时减少。

| 场景 | 优化前 µs | 优化后 µs | 观测变化 |
| --- | ---: | ---: | ---: |
| Spectrum geometry / 1024 bins | 15.57 | 7.08 | +54.5% |
| default / 128 | 78.99 | 77.74 | +1.6% |
| four bands HQ / 128 | 203.52 | 200.87 | +1.3% |
| delay / 128 | 83.82 | 80.80 | +3.6% |
| reverb / 128 | 89.07 | 88.63 | +0.5% |
| OTT / 128 | 82.32 | 77.84 | +5.5% |
| modulated delay / 128 | 86.69 | 84.01 | +3.1% |
| default / 512 | 256.35 | 259.02 | -1.0% |
| four bands HQ / 512 | 766.25 | 774.64 | -1.1% |
| delay / 512 | 278.71 | 268.91 | +3.5% |
| reverb / 512 | 298.79 | 284.48 | +4.8% |
| OTT / 512 | 272.83 | 262.55 | +3.8% |
| modulated delay / 512 | 287.21 | 283.44 | +1.3% |

频谱几何构建的下降明确。默认与四频段 HQ 的音频回调没有测到明显收益；部分启用效果的负载有几个百分点的改善，但其置信区间存在重叠，不能将小幅差异全部归因于优化。LFO 局部重绘及 OTT 空闲停止重绘由回归测试验证，未把它们换算成整个编辑器的 CPU 百分比。

## 验证

- Debug 共享代码与测试目标、Release 基准目标均构建成功。
- 全量按 `~[repaint]` 与 `[repaint]` 两批覆盖 722 个测试；最终 720 个通过，2 个原生菜单测试按现有规则跳过。
- 第一批暴露 2 个过时测试中的 4 处断言：图表按钮已进入效果机架层级，以及参数清单漏掉已存在的 OTT / 插入效果 / 模块顺序字段。核对优化前源码后，仅修正测试的递归按钮查找和独立预期清单；分别重跑 `[graph]` 及参数清单测试通过，未因此改动生产代码。
- 新增绘制测试通过 209 条断言：0.75× / 1× / 2× 下所有实际变化像素均被重绘区域覆盖，1× / 2× 另验证软件局部绘制与完整绘制逐像素一致；OTT 静止时无重绘，交互及信号变化恢复绘制。
- 独立的新旧 DSP 模块对比中，8,146,920 个音频及计量值逐值精确相等。覆盖 5 类插入效果、实际值/归一化参数、44.1 / 48 / 96 kHz、1 / 127 / 512 样本块、自动化、LFO、旁路、切换、reset、重新 prepare，以及 Tape 环绕、OTT 和 Width。此结论限定于这些探针，不代表所有宿主与所有预设。

## 后续值得实测的热点

1. 大量调制时的参数范围映射、滤波响应曲线频率投影与幅值计算。
2. 多分频带 HQ 的过采样和非线性处理；这些开销承担实际音频算法，不能直接省去。
3. 示波器多次描边、WidthGraph 整张 HiDPI 尾迹透明度衰减、OTT 渐变波纹以及顶栏装饰动画。
4. 无可见分析器时暂停音频分析捕获；需要保留重开、来源切换和 host-bypass 的新鲜度语义。

建议在宿主中按编辑器显示/关闭、1×/2× 缩放、静音/有声、HQ 开关、单/四频段和不同图表页面分别采样，再决定下一轮优化范围。
